## Base bugs found

### 1. `tinker prepare` hides a generator failure

- It exits 0 and says it wrote the route tree.
- The route generator failed, so the tree is stale.
- Doctor check 3 then says "run tinker prepare".
  That cannot help while the clash stands.
- So a route clash fails 2 checks (3 and 7),
  and check 3 sends the user the wrong way.

Repro (log: `logs/base-bug-prepare.txt`):

```bash
cd /tmp/stress-rerun/router/collision
cp breaks/tinker.tsx.break src/routes/tinker.tsx
node node_modules/@tinker/start/bin/tinker.mjs prepare
echo $?   # 0
node node_modules/@tinker/start/bin/tinker.mjs doctor
rm src/routes/tinker.tsx
```

```text
Error: Conflicting configuration paths were found … "/tinker", "/tinker".
tinker prepare: wrote .tinker/tsconfig.json, .tinker/base.json, .tinker/routeTree.gen.ts
fail  3 generated folder
      .tinker/routeTree.gen.ts misses src/routes/tinker.tsx; run tinker prepare
```

- Cause: `writeRouteTree` in `lib/prepare.mjs`
  calls `vite.resolveConfig`. The generator logs
  the error and does not throw.

### 2. Wording nits (no wrong result)

- Check 5 pass line, grammar:
  `src/router.ts export what the base reads`.
  Repro: options case, step 3.
- Check 8 pass line says
  `src/style.css is linked by the shell`

### Not a base bug: two Vite copies in this setup

- With the links the rules set, plain `vp dev`
  answers `Cannot GET /` on every path,
  `/api/health` too.
- Cause: the app's Vite is from the stress tree.
  The base's Start plugin imports Vite from the
  start-base tree. Start checks
  `isRunnableDevEnvironment` (an `instanceof`).
  The check fails, and Start skips its dev
  middleware without a word.
- A real install has one Vite copy.
- Proof, both launchers side by side:
  `logs/dev-launcher-probe.txt`.
- Other rerun areas with dev checks will hit this.

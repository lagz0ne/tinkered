# Start seam brief

Owner: lead (Claude, Start scaffold session); Sol seam writer.
Read the fixed [contributor brief](../contributor-brief.md) first.
Use the `coding-convention` skill for every TypeScript file.

## Goal

`src/scaffold/` is the fixed setup that users re-copy to update.
Today ten of its files import user files by relative path.
After this ticket it imports user code only through two seams.

- Values: shadcn's alias seam.
  shadcn rewrites `@/lib/...` to the user's `lib` alias on install.
- Types: TanStack's `Register` pattern.
  The scaffold declares an empty interface; user code fills it in.

## Done when

- No file in `src/scaffold/` imports a relative path outside it.
- Outside imports are only these:
  - `@/lib/tinker` (browser-safe values);
  - `@/lib/tinker.server` (server values);
  - `@/routeTree.gen` (generated by TanStack);
  - npm packages, `@tinker/core`, `@tinker/react`.
- No scaffold type names profile, todo, or counter.
- The scaffold compiles against a different app (proof 2).

## Shape

Move into `src/scaffold/` what only the scaffold uses:

- The sync tables now in `backend/sync.schema.ts`.
  Their JSON columns hold the envelope, not feature types.
- The envelope readers now in `contracts/sync.ts`.
  The scaffold reads only `kind`, `executionId`, revisions.
  A change body and a result body stay `unknown` to it.
- The `Database.Handle` type; it names no user schema.
- Its own error kinds (stream, scope, settings, retry).
  Feature kinds such as `TodoMissing` stay in user code.
- Telemetry state, if only the scaffold owns it.

Route the rest through the seams:

- `src/lib/tinker.server.ts` re-exports `database`, `auth`,
  `requestHeaders`, settings tags, `migrate`, proof presets.
- `src/lib/tinker.ts` re-exports `records` and any
  browser value the scaffold calls.
- A user-owned `Register` augmentation types the change,
  result, and snapshot bodies.
  Put it in `src/lib/tinker.ts`.
- `scaffold/backend/result.server.ts` loses its todo text.
  User code maps its own errors to messages.
- `scaffold/frontend/index.ts` stops re-exporting app state.

Set `aliases.lib` in `components.json` to `@/lib`.
Keep `.server.` naming: import protection blocks it in the browser.
Update `registry.json` targets and ownership for moved files.
Seam files belong to the install-once items, never `runtime`.

Keep the four forms: tags, data, resources, operations.
Seam files only re-export; they add no logic.
Keep the static graph (ADR 0088): no tag carries a resource.
A lead probe showed a tag-held resource is never built.

## Proof, all by exit code

1. A seam check script fails first on a planted relative import,
   then passes on the real tree.
   Run it as `test:seam` in this app's `package.json`.
2. A fixture app copies only `src/scaffold/`.
   It adds its own two seam files and a `Register` with a
   different payload (a note with `text`, no todos).
   `tsc --noEmit` passes on it.
3. `test:registry` installs into a consumer whose `lib` alias
   differs (for example `@/app-lib`).
   It proves shadcn rewrote the seam imports.
   It proves consumer build and types pass.
   Updating `runtime` leaves both seam files unchanged.
4. Existing gates stay green: workspace build, `vp check`,
   all app tests, `test:boundary`, `test:middleware`,
   `test:imports`, `test:registry`, strict census, prose.

# Fresh task with the tested rules

Status: blank workers staged; review-tool fixes pending.
Owner: Codex.

## Goal

Make the tested instructions and review loop the default.
Then check whether fresh writers can use them on a new app.
The first attempt is scored before any teacher feedback.
A later fix never overwrites that first result.

## Task

Build a stock-transfer desk from blank files.
It tracks two items in two places, saved moves, edits, and undo.
Editing a move must reverse its old stock change before applying its new one.
Both steps pass before anything is saved.
An open editor, typed text, and a filter must survive undo as stated.

The task is frozen in tools/writer-trial/stock/01-stock-moves.md.
Teacher checks are written from that task before writer launch.
No booking code or earlier writer app is supplied.
The task gives behavior examples, not worked code.

## Same access for all four

- Same pinned core, React, TypeScript, and browser image.
- Same full rules, task, and upgraded Jev copy, recorded by hash.
- Same four model routes as the earlier trial; high thinking.
- Fresh Paseo agent and blank app for each model.
- Only work_shell and jev tools.
- No examples, issue tracker, other apps, other submissions, or repo history.
- No host files, keys, network, or private teacher checks.
- No trial budget stops; provider failures are recorded separately.

The teacher may read the issue tracker as the reference.
Workers cannot read it.

## What to measure

For the first saved attempt of each model, record:

- Public core and real-browser checks, including failure cases.
- Type check, writer tests, and build by exit code.
- Code review of state, views, errors, and tests.
- Plain rule findings and Jev findings, with the lead's verdict.
- Writer time, tool calls, code growth, and teacher feedback count.

Report a failed check as failed even if the writer's own tests pass.
A missing or broken check is unavailable, not a pass.
Save the source, git history, session, report, tool log, and hashes.

If a real failure remains, send only that writer its own failure steps.
Start a fresh agent on its saved app with the same frozen task and tools.
Save and score the next attempt separately.
Do not send a worked fix or another model's code.

## Code review checklist

Use the same checks for every saved app:

- State: each mutable app value has a core-cell owner.
- Views: read, format, and run actions; no hidden state or effects.
- Errors: expected registry kinds are narrowed; other values are rethrown.
- Changes: failed saves write nothing; undo keeps the stated boundaries.
- Tests: use the public entry or browser, with no mocks or private state checks.
- Tools: every claimed check has output; no supplied check was weakened.

Record file and line evidence for any failure.
Plain shape checks help this review but do not replace it.
No code-size target or Jev probability threshold decides acceptance.

## Meaning of the result

This tests the full setup on another task.
It does not isolate how much improvement comes from Jev or the rules alone.
It does not prove that every future app will pass.
These instructions change the worker's context, not its model weights.

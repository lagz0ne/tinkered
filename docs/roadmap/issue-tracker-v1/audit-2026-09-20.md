## 1. Verdict

The app works and is well tested, but it is built _beside_ the library, not _on_ it.
The lead's four suspicions all confirm. Worst: the server keeps its truth in a hand-rolled
serial queue that closes over the scope (bridge.ts), six route operations are declared
inside `buildApp` and read through that closure (app.ts), and the React client holds all
form state in `useState`/`useEffect` with zero `data` cells and zero `resource` closures
(App.tsx 22 hooks, DraftView.tsx 11 hooks). Count: A=9, B=14, C=5, D=11, E=13 (52 rows).

## 3. Patterns behind the violations

Seven recurring anti-patterns. Each shows the anti-shape (≤10 lines) then the intended
shape (≤15 lines, real `@tinker/*` API, real tracker names, cast-free).

### P1. The scope as a function parameter (rows 2, 3, 4, 8, 9)

Anti-shape — the handle travels to the unit instead of the unit declaring deps:

```ts
async function publishList(
  scope: Scope.Handle,
): Promise<void> {
  const all = await scope.run(listIssues);
  scope.controller(issueList).set(all);
}
async function saveNow<T>(
  scope: Scope.Handle,
  work: (s: Scope.Handle) => Promise<T>,
) { … }
```

Intended shape — the composition root owns the scope; units declare `depends`:

```ts
// bridge.ts (root):
//   const scope = createScope({ tags, extensions: [src] });
// operations.ts: the op already declares what it needs —
export const createIssue = operation({
  label: "createIssue",
  input: parseCreateInput,
  depends: { tx: store.tx },
  run: async ({ tx }, ctx) => {
    /* insert + activity, return issue */
  },
});
// callers (routes, tests):
//   await scope.run(createIssue, { input });
```

### P2. The closure command: label-only operations over hidden functions (rows 5, 6, 10, 11, 12)

Anti-shape — the operation is a nameplate; the behavior lives where core cannot see it:

```ts
const readIssues = operation({
  label: "readIssues",
  run: () => scope.resolve(issueList),
});
const readOne = operation({
  label: "readOne",
  input: parseIssueId,
  run: (_deps, ctx) => booted.detail(ctx.input),
});
```

Intended shape — the operation IS the command (deps + admission + writes):

```ts
export const readIssues = operation({
  label: "readIssues",
  depends: { issues: issueList },
  run: ({ issues }) => issues,
});
export const readDetail = operation({
  label: "readDetail",
  input: parseIssueId,
  depends: { db: store.db },
  run: async ({ db }, ctx) => {
    /* select + parse, return detail */
  },

```

### P3. Root verbs inside unit bodies (rows 24, 26, 27, 28)

Anti-shape — `resolve`/`run`/`controller` called mid-graph instead of at the root:

```ts
run: (() => scope.resolve(issueList), // resolve inside run
  scope.controller(issueList).set(all)); // root write inside helper
await scope.resolve(src).connect(transport); // root read inside route body
```

Intended shape — `depends` delivers; the driver reads at the edge:

```ts
// inside an op/resource body: values arrive declared —
depends: { issues: issueList, src: srcSlot },
run: ({ issues }) => issues,
// at the root only:
//   scope.resolve(persistence); await scope.ready;
```

### P4. Tx-as-parameter helpers (rows 14, 18, 19)

Anti-shape — domain logic in free functions that take the transaction:

```ts
async function loadSaved(
  tx: Tx,
  id: string,
): Promise<Issues.Issue> { … }
async function writeIssue(
  tx: Tx,
  updated: Issues.Issue,
): Promise<void> { … }
async function recordActivity(
  tx: Tx,
  issueId: string,
  …
): Promise<void> { … }
```

Intended shape — ADR 0044: a resource dep delivers its value; the body reads it directly.
Helpers take VALUES, never handles:

```ts
function checkFresh(
  saved: Issues.Issue,
  baseRevision: number,
): void { … }  // value in, value out
function applyEdit(
  saved: Issues.Issue,
  input: Issues.EditInput,
  now: number,
): Issues.Issue { … }
// in the op: run: async ({ tx }, ctx) => {
//   const saved = await loadSavedValues(
//     await selectIssueRow(tx, ctx.input.id),
//   ); …
```

(Note: helpers over values are fine per 0049 §7 — the violation is the `tx` parameter,
not the extraction. Smallest honest fix is often "keep the helper, pass the row".)

### P5. React state instead of cells + effect resources (rows 29-39)

Anti-shape — the view owns state and effects React cannot clean up:

```tsx
const [title, setTitle] = useState(props.saved.title);
const [baseRevision, setBaseRevision] =
  useState(props.saved.revision);
useEffect(() => {
  fetchDetail({ input: id }).then(setDetail); …
}, [id, stamp, tick, saved]);
```

Intended shape — cells hold the form, a resource owns the stream, the view reads and runs:

```tsx
const draftTitle = data({
  label: "draftTitle",
  initial: "",
});
const saveDraft = operation({
  label: "saveDraft",
  input: parseEditInput,
  depends: {
    title: draftTitle.controller,
    patch: patchIssue,
  },
  run: async ({ patch }, ctx) => patch.run({ input: ctx.input }),
});
function EditForm() {
  const title = useData(draftTitle);
  const save = useRun(saveDraft);
  // …no useState, no useEffect
}
```

### P6. Hand-rolled lifetimes: queues, maps, waiters, sessions (rows 41, 42, 43, 44)

Anti-shape — ownership re-implemented with promises, maps, and flags:

```ts
let tail: Promise<void> = Promise.resolve();
function enqueue<T>(
  work: () => Promise<T>,
): Promise<T> { … }
const posts = new Map<
  string,
  (message: Sync.Message) => void
>();
function readWaiter(): Waiter {
  let wake: () => void = () => undefined; …
}
```

Intended shape — every effect is a resource; cleanup is `defer`:

```ts
export const saveQueue = resource({
  label: "saveQueue",
  depends: {
    tx: store.tx,
    published: issueList.controller,
  },
  factory: ({ published }, { defer }) => {
    defer(() => {
      /* drain or cancel */
    });
    return { save: (work) => runSerialized(work) };

```

### P7. Config as structs instead of tags (rows 13, 23, 51)

Anti-shape — what a test should rebind is a struct field:



## 4. Draft best-practices rules

Each rule: one imperative sentence; a smell (what to grep); a shape (≤8 lines); a why.
ALREADY = written in an ADR/convention section (cited). NEW = no written rule yet; a gap
this audit proposes.

1. **Create the scope in exactly one composition root per process.** Smell: `createScope`
   appears outside `main.ts`/`boot`. Shape: `const scope = createScope({ tags, extensions }); await scope.ready;`. Why: one owner, one close path. [ALREADY — ADR 0042, 0049 §5]
2. **Never take `Scope.Handle` as a function parameter, struct field, or closure.** Smell:
   grep `Scope.Handle` outside the root file and tests. Shape: `depends: { tx: store.tx }` then `run: async ({ tx }, ctx) => …`. Why: units stay runnable via `scope.run(op)` + presets. [ALREADY — ADR 0039 "never passed through userland", 0049 §5; NEW as a grep rule]
3. **Declare route operations at module level; mount them with the driver.** Smell:
   `operation({` inside a builder function. Shape: `route.get("/health", () => health)`. Why: tests import and run the op without booting. [ALREADY — ADR 0039, 0042]
4. **Every user action is an operation with input admission and controller deps.** Smell: a
   button handler that calls `fetch` or a closure instead of `useRun`. Shape: `useRun(saveDraft)` + `save.runAsync({ input })`. Why: `scope.run(op)` in a test does what the button does. [ALREADY — ADR 0049 §2]
5. **An operation's `run` must own its reads and writes — no forwarding to closures.**
   Smell: `run: (…, ctx) => somethingElse(ctx.input)` where `somethingElse` is not an op.
   Shape: the SQL/`tx` calls inline in `run` via declared deps. Why: one observed command path, one span. [ALREADY — ADR 0010, 0040; NEW as an explicit forwarding ban]
6. **Call `scope.resolve`/`scope.run`/`scope.controller` only at the root or in tests.**
   Smell: `scope.` inside any `run:`, `factory:`, route body, or helper. Shape: values arrive via `depends: { issues: issueList }`. Why: root verbs inside units invert ownership and break session scoping. [ALREADY — ADR 0036; NEW as a call-site rule]
7. **Pass values to helpers, never handles (`tx`, controllers, scopes).** Smell: a helper
   whose first param is `tx`, `scope`, or ends in `controller`. Shape: `applyEdit(saved, input, now)` — rows in, rows out. Why: helpers over values are pure, assertable, clock-free. [NEW — ADR 0044 implies it for deps; no rule for plain helpers]
8. **Put component form state in `data` cells, not `useState`.** Smell: `useState` in a
   component that also calls `useRun`. Shape: `const v = useData(field); const c = useController(field);`. Why: drafts survive remount, tests set fields without the DOM. [ALREADY — ADR 0049 §2, §4]
9. **Put every subscription, listener, poll, and stream in a `resource` with `defer`
   cleanup; no `useEffect` for effects.** Smell: `useEffect` in app code. Shape: `resource({ depends: {…}, factory: (deps, { defer }) => { …; return api; } })`. Why: unmount/close cleans up by construction; nothing is stopped by hand. [ALREADY — ADR 0049 §1, §4]
10. **Read exactly the cells a component renders (`useData` with selector/`isEqual`).**
    Smell: a whole-list `useData` in a detail view's dep array. Shape: `useData(issueList, (l) => l.find(i => i.id === id), (a, b) => a?.revision === b?.revision)`. Why: fine-grained re-render by construction. [ALREADY — ADR 0049 §6, 0030]
11. **Bind every environment choice as a `tag`; never a struct field.** Smell: `enabled:`,
    `baseUrl`, or `process.env` read outside the root. Shape: `tag<boolean>({ label: "draftEnabled", default: false })`. Why: a test rebinds config through `Scope.Options`, nothing else. [ALREADY — ADR 0049 §3, 0042]
12. **Share one parse per command between CLI/MCP/HTTP (zod shape IS the op input).**
    Smell: `read*Args` beside `parse*Input` beside `*Shape`. Shape: `input: z.object(schema).parse` (ADR 0046 §1). Why: two validators per command drift; one source cannot. [ALREADY — ADR 0046 §1]
13. **Give every module-level collection an owner (cell/resource/root) or delete it.**
    Smell: `new Map`/`new Set` at module or builder scope. Shape: the sender registry lives on the source extension or a resource with `defer` cleanup. Why: module state is the testability tell. [ALREADY — ADR 0049 "Module state is the tell"; NEW as a rule]
14. **Keep promise chains, waiter/queue machines, and manual close flags out of app code.**
    Smell: `tail.then(`, `new Promise`, `settled`/`closed` boolean fields. Shape: serialize through a resource; cancel through `ctx.signal`; await `scope.ready`/close. Why: hand lifetimes survive forced close and hide from observation. [NEW]
15. **Export one public seam per app boundary; tests import only the seam.** Smell: test
    imports reaching `server/operations`, `server/draft`, `tools/issues` directly. Shape: `src/index.ts` exports routes/boot/types; tests use `app.request` + `scope.run`. Why: the seam is the promise; internals stay refactorable. [ALREADY — convention Tests; NEW as applied to apps]

## 5. What the app does right

- `server/operations.ts:86-108` — `createIssue` declares `input: parseCreateInput` + `depends: { tx: store.tx }` and writes insert + activity in its own `run`: the ADR 0041 shape verbatim.
- `server/operations.ts:184-192` — `listIssues` is a real dep-declared read op, reusable via `scope.run(listIssues)` in tests (`issues.test.ts:232` does exactly this).
- `server/store.ts:74-79` — the `drizzleStore` frame: `open`/`close` with the driver import inside `open`, config as `store.config(dataPath)` tag — matches ADR 0041 and the 0042 lazy policy.
- `server/app.ts:33-52` — `onError` maps `IssueNotFound`→404, `IssueConflict`→409, parse failures→400 inside the driver slot: the ADR 0040 §2 error-mapping shape.
- `tools/issues.ts:117-215` — five ops carry both `command(…)` and `tool(…)` meta with `commands(op)`/`tools(op)` bindings: the ADR 0046 "one declaration serves every harness" shape.
- `server/bridge.ts:76-81` — `bootScope` installs `source()` as an extension and awaits `scope.ready`: the ADR 0050 composition-root shape.
- `client/sync.ts:119-124` — `connectTab` installs `subscribe(transport)` and awaits `scope.ready` before returning: the subscriber half of the same shape.
- `tests/issues.test.ts:21-46` — first test drives boot → save → `memoryPair` sync → guest `resolve`, asserting cross-tab visibility with no mocks and no sleeps.
- `src/errors.ts:1-43` — one registry with `fail`/`raise`/`isError`, callers narrow by control flow (`if (!isError(e, "IssueConflict")) throw e`): the convention §2 shape, matching the playground idiom.
- `client/api.ts:1-58` — the http client frame (`api.operation` with `request`/`response`) is the correct edge for browser→server commands; the CLI/MCP ops reuse it as subflow deps instead of re-implementing HTTP.

## 6. Core feedback

Friction or missing affordances in `@tinker/*` that pushed the app into a violation. Each
names the API, the call site, and what would have made the right shape possible.

1. **No scoped "publish after commit" primitive.** `bridge.ts:33-41` (`publishList` +
   `saveNow`) exists because a request-session write cannot reach the root cell: PLAN
   boundary 4 ("session cell writes do not update the source scope's cells") forces every
   app to hand-roll the bridge, and this app's bridge (root `resolve` + root `controller.set`
   from a helper) is exactly the shape ADRs 0036/0044 forbid. A sanctioned primitive —
   for example, a session-commit hook that delivers the committed value to a root-declared writer —
   would have made rows 2, 3, 27, 28 conforming instead of violating.
2. **`scope.session(work)` invites closure commands.** `bridge.ts:38-41` runs saves as
   `scope.session((s) => s.run(createIssue, { input }))` inside a serializer. The inline
   session callback is unobserved (no span, no label) and untestable except through boot.
   A named/labelled session-run (or a built-in "run op in a short session and publish")
   would have kept the save path on the observed rails.
3. **No built-in way to run one call at a time on a single-connection store.** `bridge.ts:44-62`
   hand-rolls `tail`/`enqueue` because PGlite serializes transactions. The PLAN (boundary 3)
   tells each app to "serialize short mutation transactions … and explain the reason" —
   that is, every PGlite app re-invents the queue. A `drizzleStore` serial option (or a core
   mutex resource recipe in the drizzle README) would delete rows 4 and 41.
4. **Sync v1 has no client→server write path, so the app built a second protocol.**
   `app.ts:86-230` hand-rolls SSE+POST (`posts` map, `owned` wrapper, register parsing)
   around the one-way `source`/`subscribe` pair. The withdrawn LWW `set`/`ack`/`reject`
   design (ADR 0048 §4-5) is the missing piece; until it returns, every multi-tab app
   duplicates this ~150-line transport. The `Sync.Transport` passthrough works but the
   _server-side fan-out registry_ has no owner — so the module-level `Map`.
5. **No per-form `data` helper for React (family for forms?).** The client holds 30+
   `useState` slots because there is no documented "form cell" pattern: one cell per field
   is verbose (label + parse + controller dep each), one cell per form needs a shape the
   `parse` edge must bless. A `form({ fields })` helper or a worked form example would
   have made rows 29-35 the path of least resistance instead of `useState`.
6. **Harness runs need a managed-session recipe.** `draft.ts:54-100` (`runDraft`) re-decides
   graceful-vs-forced close, abort wiring, watch/unsubscribe, and outcome mapping around
   `owner.createSession`. A recipe — "run a turn in a child session with signal + watch,
   close gracefully, map `Scope.Result`" — either as docs or as a harness helper, would
   collapse 60 lines into the same ~10 every app needs (row 44).
7. **Route-level streaming still needs scaffold per route.** `app.ts:240-377`
   (`draftStream`/`draftOpened`/`readRunState`/`readWaiter`) builds abort fan-out, queue
   pump, and terminal framing by hand around the `stream` helper. The helper covers emit;
   the _input side_ (parse → existence check → abort-aware run → terminal event) is
   unowned. A `streamRoute(op, { terminal })` shape in `@tinker/hono` would cover it.

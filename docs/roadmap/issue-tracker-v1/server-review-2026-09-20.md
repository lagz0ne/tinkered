# Server usage review — `apps/issue-tracker/src/server` against the `@tinker/*` primitives

Date: 2026-09-20. Reviewer: lead (Claude). Scope: `server/*.ts`, `store.ts`, the server seam tests.
Companion: the contributor audit `audit-2026-09-20.md` (scope-passing, thin wrappers, React client).

## The primitives, as the packages define them

```text
main.ts (composition root)
  scope = createScope({ tags: [store.config(path), sync(issueList), ...routeBindings], extensions: [source()] })
  await scope.ready                         ADR 0050: nothing runs before every extension started
  app   = await honoApp(scope, { onError }) ADR 0042: routes are scope config; 0039: one session per request
  ...
  await scope.close({ graceful: true })     ADR 0039: waits for in-flight request sessions

one request  = one session               tinker()                   ADR 0039
  handle(op) = inline op, span, log, error map, runs `op` as a subflow   ADR 0040
  op.depends = { tx: store.tx }          session resource; commit == session success   ADR 0041
  ctx.signal aborts when the client disconnects; ctx.clock is the ambient clock         ADR 0034
```

The server has ONE real gap the primitives do not close: a session's cell write does not reach the
root cell, so "publish the committed list to the sync source" needs a root write after the session
closed (PLAN boundary 4; core-feedback tracker/t01). Everything below is judged with that gap taken
as given. The gap explains `saveNow`; it does not explain the rest.

## What the server does right (keep)

- `operations.ts:86-194` — the five domain operations are the right shape: `input:` parser at the door, `depends: { tx: store.tx }` for writes and `{ db: store.db }` for reads, `ctx.clock` for time, registry errors only. `loadSaved`/`writeIssue`/`recordActivity` taking `tx` as a _value_ is fine: `tx` is data, not the scope.
- `store.ts:71-77` — `drizzleStore` frame with `config` as the tag; PGlite path `undefined` = in-memory for tests.
- `shared/issues.ts:306-312` — one `issueList` cell with `parse` and `synced` meta, shared by server and client (ADR 0048).
- `app.ts:30-50` — one `onError` map for the app's registry errors → statuses (the ADR 0040 slot).
- `bridge.ts:44-63` — the serial queue is honest about PGlite being single-connection (PLAN boundary 3) and is documented as a workaround in core-feedback.

## Feedback for the packages (candidates for `docs/roadmap/core-feedback.md`)

- **F1 (hono):** `HonoScope.Route.input` is `(c) => unknown` and is not awaited (`readRoute`, `packages/hono/src/index.ts:~290`). A JSON body route must pre-read the body outside `handle`, which is why R5 exists four times. Ask: accept `unknown | PromiseLike<unknown>`.
- **F2 (core):** a session's cell writes are invisible at the root and there is no "after this session closed successfully" hook. This forces R6/R8 (publish after `scope.session`) and R9 (hold the session handle to watch `triage.text`). Second asker after tracker/t01; the workaround now spans two features. Candidate: a session-close hook on the run's `ctx`, or an extension `close` hook that also sees session closes.
- **F3 (hono):** `stream`'s `emit` resolves when enqueued but is not safe to call from a sync `Sync.Transport.send`; the README recipe uses `void emit(...)` which the convention forbids. Ask: `emit` serializes internally, or `stream` exposes a `Sync.Transport`-shaped writer.

## Suggested order if this is fixed

1. R1, R2, R12 (one line each, real behaviour).
2. R3 + R4 together: routes as scope config, `handle(createIssue)` directly; `saveNow` becomes an extension or a root-level `afterSave` that only publishes (keeps the serial queue).
3. R8 + T1: `main.ts` and the tests own the scope; delete `Booted.Composed`.
4. R10/R11/R9 last; they depend on F1–F3 for a clean shape.

# Bridges — where raw I/O enters the scope

Ticket: `jev/bridge-pattern`.
Date: 2026-09-27.
Base: `jev/handrolled-survey` at `55fdee0` (on `main` `661d5e0`).
Input: [the survey](2026-09-27-survey.md), 32 boundary and 2 bridge cases.

This file proposes one rule and classifies every case under it.
It changes no code and adds no rule to `tools/jev`.

Two words, defined once:

- **Raw I/O** — a source tinker does not own: an `EventSource`, stdin, a DOM event, `postMessage`, a signal, a child process, an SDK callback.
- **Bridge** — the one unit that turns raw I/O into tinker verbs: cell writes, sessions, runs.

## 1. The rule

1. **Raw I/O lives in the unit whose lifetime it shares.**
   A resource (or one run) opens it in its body, writes its own cells, and `ctx.defer` closes it.
2. **An extension bridges only what needs the scope.**
   Outside events that open sessions or run operations for the scope's whole life enter through an extension; it resolves the raw unit, it never builds it before `createScope`.
3. **A status has one writer: its owner.**
   Copying our own object's status into a cell is never a bridge; the owner writes the cell.
4. **What a library contract demands stays inside the unit that fulfills it.**
   The listener sets and close flag behind `Sync.Transport`, or an `AbortController` an SDK takes.

### Precedent

- **Clauses 1–2 borrow init and its daemons (ADR 0060).**
  Init hands a daemon its socket and reaps it; the daemon never exists before init.
  Ours: `createScope` is init; an extension is a daemon; a resource is the file it opens.
- **Reconnect borrows systemd's `BindsTo=` and `Restart=`.**
  `BindsTo=`: a unit stops when the unit it binds to stops.
  Core's release cascade already does this (ADR 0063).
  `Restart=on-failure` with `RestartSec=`: the unit comes back after a wait.
  Core has no restart; section 3 puts it in `subscribe`.
- **Clause 3 is the single-writer rule** (glossary: derivation).
- **Clause 4 is ADR 0048's transport contract.**
  The contract is the one place a listener set is honest.

### Where ours is simpler

- A unit's lifetime is its owner's: scope, namespace, or session.
  There is no separate "raw I/O lifetime" to name.
- Clause 2's test is one question: does it need the scope handle?
  Only an extension's `start` gets one (ADR 0051, rule 2).

### Clauses tried and cut

- **"A raw source whose lifetime is the scope's is an extension."**
  Cut: `immersive` and `runtime` in the playground live as long as the scope.
  They only write cells, so a resource is enough.
- **"The process edge stays at the root."**
  Cut: its one case (`process:201`) is `@tinker/process`'s own `main`.
  ADR 0056 already says it; clause 4's driver class covers it.

### A correction to the brief

- An extension's ctx has `clock`, `random`, `signal`, `defer`.
- Its `log` and `obs` are switched off: `packages/core/src/index.ts:2879`–`2880` (`OFF_LOG`, `OFF_OBS`).
- So a bridge extension logs nothing.
  A resource logs.
  One more reason clause 1 puts the raw I/O in a resource.

## 3. The sync friction

The user (2026-09-27):

- "Not sure why connection needs to be before the scope exists. Controlling the logical dependency on async is the strength of the tinker model."
- "Connection needs retry too, so it is natural to have reconnection and latest access instead of strict static."

### Today

- `subscribe(transport, wiring)` takes a built `Sync.Transport`: `packages/sync/src/index.ts:306`.
- So the tracker builds the wire in `start` before `createScope`: `apps/issue-tracker/src/client/main.tsx:29`.
- So the wire has no `ctx`, no cells, no endpoint operations.
- It rebuilds each by hand: `Math.random`, a status getter, `onStatus`, an `AbortController`, a replay of the last register.

### The shape: the wire is a unit

- The wire is a `resource`.
  Its async factory opens the `EventSource` with `ctx.random` and `ctx.signal`.
  `ctx.defer` closes it.
  It writes `connection` itself.
- `subscribe` takes the resource handle, not a value.
  It resolves the wire inside the scope, so `ready` still waits for the first snapshots.
- Reconnect is `release(tabWire)`.
  `subscribe` holds the wire through a resource of its own, `attached`, that depends on it.
  Release tears `attached` down first (ADR 0063 §4); its `defer` sees `{ status: "released" }`.
  That `defer` is the one restart path: wait, then resolve `attached` again.
  Resolving `attached` rebuilds the wire first, so it always gets the latest instance.
- Retry waits with `ctx.clock.sleep(backoff(n), ctx.signal)`.
  A test clock drives it; a scope close aborts it.

### What core has today

- **Release unlinks and cascades.**
  `Scope.Handle.release` (`packages/core/src/index.ts:628`) runs `releaseNode` (`:4565`).
  Dependents are torn down first (ADR 0063 §3–4).
- **The next resolve builds a fresh generation.**
  `index.ts:625`–`627`; `invalidateResource` bumps `gen` (`:4458`).
  A late build from the old generation never publishes (`packages/core/README.md:445`).
- **A released instance's `defer` gets `{ status: "released" }`.**
  `Scope.End` at `index.ts:522`.
  A scope close gives `success` or `cancelled` instead, so a close never restarts.
- **A failed build is sticky until release.**
  `README.md:449`, and a dependent's cached failure clears with its dependency (`index.ts:3273`–`3275`).
  So a retry releases before it resolves.
- **A resource may write a cell through a controller edge.**
  `liveness` does it today (`services.ts:28`).

### What core is missing

1. **Nothing restarts a released unit.**
   Release is pull-only: dependents stop, but rebuild only when someone resolves.
   `ResourceController` has only `resolve` and `get` (`index.ts:283`–`286`); no one is told a new instance exists.
   So "the latest instance" works by pull: `scope.controller(r).resolve()` after a release.
   `subscribe` does that pull once, in its restart.
   A core `restart` option (systemd's `Restart=`) would move it into core.
   Core feedback: one asker.
2. **Only the scope handle releases.**
   `Operation.Ctx` (`index.ts:227`) and `Resource.Ctx` (`:255`) have no `release`.
   React has `useRelease` (`packages/react/src/index.ts:495`).
   So the wire cannot release itself on error; it fires `onClose` and `subscribe` releases.
   So a `reconnect` operation cannot exist; a button calls `useRelease`.
   This collides with `tracker/reconnect`'s brief ("reconnect an operation").
   Core feedback: one asker.
3. **A cell write does not rebuild a resource that depends on it.**
   `writeCell` (`index.ts:1340`) only runs watchers.
   So "bump an attempt cell" is not a reconnect path; only release is.

### The sync signature

```ts
// packages/sync
type Built = Transport | Promise<Transport>;
export type Wire = Resource.Handle<Built>;
export function subscribe(
  wire: Sync.Wire,
  wiring: Sync.Wiring & {
    readonly backoff?: (n: number) => number;
  },
): Scope.Extension<Sync.Subscription>;
```

Inside `start` (the scope is the one `start` got):

```ts
const attached = resource({
  label: "sync.attached",
  depends: { t: wire },
  factory: async ({ t }, a) => {
    const stop = attach(scope, t, cells);
    a.defer((end) => {
      stop();
      if (end.status === "released") restart();
    });
    await firstSnapshots(); // SyncNotReady
  },
});
await scope.controller(attached).resolve();
await next();
```

The restart, the only retry loop, written once:

```ts
async function restart(): Promise<void> {
  for (let n = 0; ; n += 1) {
    await ctx.clock.sleep(backoff(n), ctx.signal);
    try {
      await scope.controller(attached).resolve();
      return;
    } catch {
      scope.release(wire); // clear sticky failure
    }
  }
}
```

`attach` sends `register` for every key the cells hold now.
That is the same code as the first connect, not a saved message.

### The tracker's wire under it

```ts
export const tabWire = resource({
  label: "tabWire",
  depends: {
    post: postSync,
    status: connection.controller,
  },
  factory: async ({ post, status }, ctx) => {
    status.set(CONNECTING);
    const id = ctx.random.uuid();
    const stream = new EventSource(`/sync?client=${id}`);
    ctx.defer(() => stream.close());
    await opened(stream, ctx.signal);
    status.set(LIVE);
    return tabTransport(stream, id, post, status);
  },
});
```

- `tabTransport` holds `arrivals`, `partings`, and the POST tail (clause 4).
  `stream.onerror` writes `DROPPED` and fires `partings`.
- `postSync` is a new endpoint operation in `client/api.ts` (S24).
- The root: `subscribe(tabWire, { cells: [[issueList, "issues"]] })`.
  No `wire` tag, no `liveness`, no `reconnect` operation.
- `WireStatus` loses `failed`: after `ready` the wire retries forever.
  Before `ready`, a failed first build still rejects `ready` and the dead page renders, as today.

### What changes in `packages/sync`

- `subscribe`'s first parameter: a `Sync.Transport` becomes a `Sync.Wire` handle.
- `start` builds `attached` per `subscribe` call; the listener code moves into its factory.
- The `close` hook shrinks: core's close tears down `attached` and the wire.
- `Subscription.close()` needs one `stopped` flag, so its own release does not restart.
- New `backoff` in the wiring; default a capped doubling (assumed: 250 ms to 8 s).
- `source` does not change: a server wire is per request, owned by its run.

### The cost

- A breaking public signature across packages: an impact block and `refs` at review (ADR 0065).
- Callers: `apps/issue-tracker/src/client/main.tsx:30`, `examples/sync/basic.ts`, `packages/sync/README.md`, `examples/README.md`, `docs/glossary.md`.
- Tests: 23 `subscribe(` calls in `packages/sync/tests/sync.test.ts` and 2 in `apps/issue-tracker/tests/issues.test.ts` wrap their `memoryPair` side in a resource.
- New seam tests: release re-registers; backoff under a test clock; a sticky failure retried; close never restarts; `Subscription.close` never restarts.
- A new ADR amends ADR 0048 §6: the transport stays userland's, but it is a unit.
- `attached` is a resource built inside a driver's `start` and closes over the scope.
  The `hono` middleware already does this; rule 5 exempts a driver's `src` in practice, not in words.
- The tracker loses about 120 lines: `reconnectingTransport`'s reopen, `liveness`, `reconnect`, the `wire` tag.

### Rejected

- **`subscribe((ctx) => transport, wiring)`: a factory that gets the extension ctx.**
  It gets `random`, `clock`, `signal`, `defer`.
  It gets no cells, no endpoint operations, no `log` (switched off).
  Reconnect stays inside the factory, by hand: no generation, no release, no cascade.
  It fixes the symptoms the survey counted, not the cause.

### Assumptions

- A resource resolves inside an extension's `start` before `next()`.
  `source` already reads cells there; not probed for a resource.
- An extension ctx's `signal` aborts on every close, graceful too.
  If not, `restart` also checks a `stopped` flag set in the `close` hook.
- `EventSource` takes a relative URL in the browser; the tracker serves `/sync` on the page's origin.

## 4. What the checks become

One line per clause: who holds code to it.

### Clause 1 — raw I/O lives in its unit

- **S24 `rawFetch`** (plain), widened.
  Today it skips `EventSource` and `WebSocket` ("a userland transport owns them").
  New second shape: `new EventSource(`, `new WebSocket(`, `addEventListener(`, `process.stdin.on(` outside a unit body (an operation `run`, a resource `factory`, an extension `start`).
  Hits today: `connection.ts:93` only.
  `server/sync.ts:52` is a helper called from a run; it opens nothing raw, so it is not hit.
- **`effectWithoutDefer`** (judge, covered): the unit closes it in `ctx.defer`.
  Add its false side: "a close method a library contract requires, called from the owner's defer" (survey P4).
- **S20 `rawRandom`, S21 `rawClock`** (plain): inside the unit, read `ctx.random` and `ctx.clock`.

### Clause 2 — an extension bridges only what needs the scope

- **Rule 2's gate** (`scripts/two-hands.sh`, a validate lane): only `start` holds the scope.
- No new check.
  A wire built before `createScope` is caught by S24's second shape.

### Clause 3 — a status has one writer

- **S23 `handSubscribe`** (plain): a getter plus `onX` over a listener set.
  It flags the source of the copy (`connection.ts:192`).
- **`stateOutsideCell`** (judge, covered): a status kept outside a cell.
- **`bridgesOwnStatus`** (judge): a second unit copies our own status into a cell.
  True cases: `services.ts#liveness`, `actions.ts#reconnect`.
  Add to its false side: "an extension or resource that writes a cell from raw I/O it opened itself — that is the owner writing".
  Still 3 true cases short of ADR 0054's floor; seed from writer-trial runs.

### Clause 4 — contract internals stay inside

- **S23's skip:** `onMessage`/`onClose` on an object that also has `send` and `close`.
- **`handRolledLifetime`** (judge, covered): its false side keeps per-attempt promises and per-wire queues.
  Reword its false side from "a userland transport that reconnects" to "a transport's own listener sets, per-instance send order, and open promise".
  Reconnecting is no longer the transport's job.

### Best-practices rule 13, the new wording

Rule:

> No hand-rolled lifetime: no promise tails, waiters, queues, maps of senders, or manual close flags.
> Raw I/O lives in the unit whose lifetime it shares: a resource or one run opens it, writes its own cells, and `ctx.defer` closes it.
> An extension bridges only what needs the scope: sessions or runs from outside events.
> A status the app reads is a cell its owner writes; no getter plus `onX`, and no second unit copying it.
> Only what a library contract demands stays hand-kept, inside the unit that fulfills it: `Sync.Transport`'s listener sets and close flag, one open promise, the send order.

Smell (grep), added to today's:

- `onStatus(`, `status()` read then `.set(` in another unit.
- `new EventSource(` or `new WebSocket(` outside a `factory`, `run`, or `start`.

Shape:

```ts
resource({
  depends: { status: cell.controller },
  factory: async ({ status }, ctx) => {
    const s = new EventSource(url);
    ctx.defer(() => s.close());
    status.set(LIVE);
    return transport(s);
  },
});
```

Goal: fewer lines.

The old exception, "a userland transport that reconnects", is gone.
Reconnect is a release; `subscribe` restarts.

# Hand-rolled survey — code that redoes what tinker gives

Ticket: `jev/handrolled-survey`.
Date: 2026-09-27.
Base: `main` at `661d5e0`.

This survey finds code that builds by hand what tinker already gives.
Then it proposes one check per pattern.
It changes no code and adds no rule.

## Counts

- **Patterns:** 18.
- **Occurrences:** 87.
- **Hand-rolled:** 19 (tinker should do it).
- **Boundary:** 32 (raw I/O a driver or transport must own).
- **Fine:** 36 (each says why).
- **Proposed plain rules:** 6 (S20–S25).
- **Proposed Jev judges:** 2.
- **Covered by a live rule or judge:** 7 patterns.
- **No check:** 3 patterns (nothing hand-rolled, or tinker does not give it).

## How to read this

- **Hand-rolled** — tinker gives this; the code should use it.
- **Boundary** — raw I/O (a socket, an `EventSource`, a child process, an SDK) that a driver or a userland transport must own.
- **Fine** — a reason is given on the next line.
- One occurrence is one construct in one unit.
  Several lines of the same construct in one unit count once.
- **plain** — plain code on the syntax tree can find it (`tools/jev/plain.mjs`).
- **jev** — needs a yes/no judge.
- **covered** — a live rule or judge already asks it.
- **repo-advisory** — `lint.mjs` over the repo.
- **writer-gate** — the writer-trial gate (ADR 0068).

## Where I looked

- `apps/issue-tracker`, `apps/playground`, `examples/**`: all source.
- `packages/*/src` except `packages/core` (the provider).
- `apps/website` holds only the Vite starter; it uses no tinker. Skipped.
- Test files: scanned; they hold only test-driver timers and strings. Not counted.

## What tinker gives (checked in the source)

- **cell** — `data`, read with `controller.watch` or `useData`.
- **cleanup** — `resource` with `ctx.defer`; `ctx.signal` aborts on close.
- **randomness** — `ctx.random.next()` / `.uuid()`; `makeTestRandom(seed)` for tests.
- **time** — `ctx.clock.currentTimeMillis()` / `.sleep(ms, signal)`; `makeTestClock` for tests.
- **logs** — `ctx.log` and spans.
- **recover** — `op.settle(call)` returns a Result and never throws (ADR 0067).
  It works through a bare operation dependency too.
- **config** — `tag`; `@tinker/process` has an `env` tag.
- **per-key state** — `namespace`; `family` for synced cells.
- **retry** — `@tinker/http` `config({ retry })`, for endpoint operations only.
- **run wrappers** — an extension `run` hook.

Corrections to the brief's catalog:

- `family` lives in `@tinker/sync`, not core.
  It keys synced cells only.
- Core has no "a newer call wins" for operation runs.
  It drops a stale build only for a resource that is released.
- Core has no "wait until a cell holds a value, or abort".
- `@tinker/http` retries only endpoint operations; an SDK call has no tinker retry.

## The reference case

`apps/issue-tracker/src/client/connection.ts` (being rewritten on `tracker/reconnect`).
It shows up in 10 of the 18 patterns.

Why it lives outside the scope:

- `subscribe(transport, wiring)` takes a transport that is already built.
  Source: `packages/sync/src/index.ts:306`.
- So the wire is made before `createScope`.
- So it cannot reach `ctx.random`, `ctx.clock`, `ctx.signal`, `defer`, or cells.
- Every check below flags a symptom.
  The cause is that signature (see "Core feedback").

Why the old checks let it through:

- `stateOutsideCell` flagged it and it was labeled true.
- The label's reason says best-practices rule 13 accepts it.
- Rule 13's exception covers "a userland transport that reconnects".
- `handRolledLifetime` names the same exception in its false side.
- So a reviewer read the flag as allowed.

## P1 — Hand-made subscribe

A listener `Set` plus `add`/`delete` plus a loop that calls them.
Tinker gives: a `data` cell plus `watch` or `useData`.

Occurrences:

- `apps/issue-tracker/src/client/connection.ts:57` — `watchers` behind `onStatus` (:192), fired by `flip` (:70).
  Verdict: **hand-rolled**.
- `apps/issue-tracker/src/client/connection.ts:58` — `arrivals` behind `onMessage`.
  Verdict: **boundary**: the `Sync.Transport` type asks for `onMessage`.
- `apps/issue-tracker/src/client/connection.ts:59` — `partings` behind `onClose`.
  Verdict: **boundary**: `Sync.Transport` asks for `onClose`.
- `apps/issue-tracker/src/server/sync.ts:57` — `arrivals` behind `onMessage`.
  Verdict: **boundary**: the server half of the same contract.
- `apps/issue-tracker/src/server/sync.ts:58` — `partings` behind `onClose`.
  Verdict: **boundary**.
- `examples/sync/hono.ts:63` — `arrivals` behind `onMessage`.
  Verdict: **boundary**.
- `examples/sync/hono.ts:64` — `partings` behind `onClose`.
  Verdict: **boundary**.
- `packages/sync/src/index.ts:77` — `family`'s own `arrivals` behind `onMember`.
  Verdict: **boundary**: this is the provider of `family`.
- `packages/sync/src/index.ts:468` — `memoryPair`'s four listener sets.
  Verdict: **boundary**: the shipped test transport.
- `apps/playground/src/bench/runners.ts:264` — `setters` array.
  Verdict: **fine**: the plain-React control the benchmark measures against.

Proposed check: **plain**, `S23 handSubscribe`.

- Shape: a property or method named `on[A-Z]…` whose function calls `S.add(param)` and returns a function that calls `S.delete(param)`.
  `S` is a `new Set(…)` or `[]` declared in an outer scope.
- Skip: `onMessage` or `onClose` on an object literal that also has `send` and `close` keys.
  That is the `Sync.Transport` contract.
- Message: "hand-made subscribe: keep the value in a data cell; readers watch it or read it with useData".
- Fix: `const status = data<WireStatus>({ label: "wire.status", initial: "connecting" })`.
- Lanes: both. Repo-advisory runs it on `apps/` and `examples/`; packages are the providers.
- Hits today with the skip: 1 (`connection.ts:192`).

## P3 — A bridge that copies a status into a cell

A bridge here means: a unit that reads another object's status and writes a copy into a cell on every change.
Tinker gives: the owner writes the cell itself (glossary: derivation).

Occurrences:

- `apps/issue-tracker/src/client/services.ts:26` — `liveness`: `line.status()` (:30) and `line.onStatus` (:31) copied into `connection`.

- `apps/issue-tracker/src/client/actions.ts:383` — `reconnect` writes `pending`/`failed` around `line.reconnect()` (:387, :391, :394).
  Verdict: **hand-rolled**: a second writer of the same fact; `liveness` skips `connecting` to avoid clobbering it (`services.ts:23`).
- `apps/issue-tracker/src/tools/main.ts:29` — stdin `end` and `server.onclose` set `stopping`.
  Verdict: **boundary**: raw stdin and the MCP SDK.
- `examples/mcp/cli.ts:35` — same shape.
  Verdict: **boundary**.
- `apps/playground/src/lib/fullscreen.ts:44` — `fullscreenchange` sets `mode`.
  Verdict: **boundary**: the DOM owns full screen.
- `apps/playground/src/services.ts:143` — iframe `message` sets `status`.
  Verdict: **boundary**: postMessage from the preview.

Proposed check: **jev**, `bridgesOwnStatus` (unit judge).

- Question: "Does this resource or operation copy a status that our own code keeps elsewhere — read through a getter such as status() and followed through an onX subscribe, or set around a call to that object's method — into a data cell, so the same fact has two homes and two writers? A raw platform source (a DOM event, process.stdin, a postMessage, an SDK callback) is not our own code."
- `true` means: the cell mirrors a status another userland object keeps and announces through its own subscribe.
- `false` means: the cell is written from a raw platform event or SDK callback, or the unit owns the state it writes.
- True labels found: `services.ts#liveness`, `actions.ts#reconnect` (2).
- False labels found: `fullscreen.ts#immersive`, `playground/src/services.ts#runtime`, `tools/main.ts#stdio`, `examples/mcp/cli.ts#stdio`, `playground/src/services.ts#persistence`, `server/draft.ts#draftBody` (6).
- Short of ADR 0054's floor by 3 true cases.
  Seed them from writer-trial runs before calibrating.
- Once P1 and P2 are fixed, this bridge has nothing left to copy.

## P14 — A run's failure dropped

`.then(undefined, () => undefined)` on a run, or a bare `catch {}` around one.
Tinker gives: `settle` returns a Result and never throws.
A bare catch does not recover a panic: it stays sticky (ADR 0067).

Occurrences:

- `apps/issue-tracker/src/client/services.ts:46` — `check.run().then(undefined, () => undefined)`.
  Verdict: **hand-rolled**: `check.settle()`.
- `apps/issue-tracker/src/client/services.ts:75` — `load.run({ input: id }).then(undefined, () => undefined)`.
  Verdict: **hand-rolled**: `load.settle({ input: id })`.
- `apps/issue-tracker/src/client/actions.ts:310` — `catch {}` around `check.run()`; returns a made-up `{ enabled: false }`.
  Verdict: **hand-rolled**: its TSDoc says "never throws", but a panic still fails the layer.
- `apps/issue-tracker/src/client/drafter.ts:90` — `reader.cancel()` rejection dropped (also :95, :141).
  Verdict: **boundary**: a web stream's own promise.
- `apps/issue-tracker/src/client/connection.ts:133` — `gated` marked handled.
  Verdict: **boundary**: the wire's own open promise.
- `packages/sync/src/index.ts:405` — `noteRejection`.
  Verdict: **boundary**: provider.
- `apps/playground/src/services.ts:81` — `compile.run(…).then(ok, err)`.
  Verdict: **fine**: narrows with `isError` and rethrows the rest.

Proposed check: **plain**, `S22 droppedRun`.

- Shape A: `X.then(A, B)` or `X.catch(B)` where `X` is a call of a member named `run`.
  `B` is an arrow whose body is `undefined`, `{}`, or an empty block.
- Shape B: a `try` whose block awaits a call of a member named `run`, with a `catch` that has no parameter.
- Message: "a run's failure is dropped: call settle(call) and branch on its Result; a bare catch leaves a panic sticky (ADR 0067)".
- Fix: `const r = await load.settle({ input: id })`.
- Lanes: both.
- Hits today: 3 true, 0 false.
- Census `S04` sees `.catch(() => undefined)` but not the `.then(undefined, …)` form.
  `plain.mjs` has no `S04` at all.

## Core feedback these findings raise

For `docs/roadmap/core-feedback.md`; this ticket does not write there.

- **`subscribe` takes a built transport.**
  The tab wire must exist before the scope, so it cannot use `ctx.random`, `ctx.clock`, `ctx.signal`, `defer`, cells, or endpoint operations.
  That one fact drives P1, P2, P4, P5, P6, and P15 in `connection.ts`.
  Ask: let `subscribe` take a transport resource.
- **No "a newer call wins" for an operation run** (P13).
  Two units build it by hand: `playground/src/services.ts#bundler`, `client/drafter.ts#drafter`.
- **No "wait until a cell holds, or abort"** (P16).
  Three copies; one leaks.
- **`Sync.Transport` is a callback contract.**
  Every userland transport rebuilds the same two listener sets and close flag: 3 copies (P1, P4).
- **`useSpans` does not re-render on a new span** (`examples/react/basic.tsx:57`).

The first row, as code:

```ts
// the wire is built before any scope:
const wire = reconnectingTransport(origin);
const scope = createScope({
  extensions: [subscribe(wire, { cells })],
});
// so no ctx.random, no defer, no cell for status
```
